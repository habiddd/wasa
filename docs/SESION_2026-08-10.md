# Cambios en la sesión del 10 de agosto de 2026

## Resumen

Se reemplazó **Evolution API** como canal de WhatsApp por **Baileys** (WhatsApp Web no oficial, gratuito). Se corrigieron inconsistencias de credenciales y se puso en marcha el proyecto completo con Docker Compose.

## Cambios realizados

### 1. Reemplazo de Evolution API por Baileys

**Motivación:** El usuario solicitó usar el servicio no oficial de Baileys en lugar de Evolution API, ya que es totalmente gratuito y no requiere configuración adicional de instancias.

#### Archivos nuevos:
- **`baileys-bot/package.json`** — Dependencias: `@whiskeysockets/baileys`, `@hapi/boom`, `axios`, `qrcode`
- **`baileys-bot/Dockerfile`** — Imagen basada en `node:20-alpine` con `git` instalado (necesario para Baileys)
- **`baileys-bot/index.js`** — Servicio de Baileys que:
  - Genera el código QR en la terminal
  - Envía el QR al webhook de Flask (`/webhook/qr`)
  - Reenvía mensajes entrantes a Flask (`/webhook/whatsapp`)
  - Expone un endpoint HTTP `/send` para que Flask envíe mensajes de vuelta

#### Archivos modificados:
- **`docker-compose.yml`**:
  - Reemplazado el servicio `evolution-api` con `baileys-bot`
  - Agregado volumen `baileys_sessions` para persistir credenciales
  - Actualizadas variables de entorno del servicio `flask-app`:
    - `EVOLUTION_API_URL` → `WHATSAPP_API_URL`
    - `EVOLUTION_API_KEY` → `WHATSAPP_API_KEY`
  - Agregado `FLASK_QR_URL` al servicio `baileys-bot`

- **`flask-app/app/whatsapp_client.py`** (nuevo, reemplaza a `evolution_client.py`):
  - Cliente HTTP para enviar mensajes de texto a través del servicio de Baileys

- **`flask-app/app/config.py`**:
  - Actualizado para usar `WHATSAPP_API_URL` y `WHATSAPP_API_KEY`

- **`flask-app/app/routes/webhook.py`**:
  - Actualizado para usar `whatsapp_client` en lugar de `evolution_client`
  - Agregado endpoint `/webhook/qr` (GET y POST) para recibir y servir el código QR

- **`.env`**:
  - Reemplazadas variables de Evolution API (`EVOLUTION_API_KEY`, `EVOLUTION_SERVER_URL`, `EVOLUTION_INSTANCE_NAME`) con `FLASK_API_KEY`

- **`.env.example`**:
  - Actualizado para reflejar las nuevas variables

- **`README.md`**:
  - Actualizado completamente para documentar el uso de Baileys en lugar de Evolution API

### 2. Corrección de credenciales en Postgres

**Problema:** La contraseña de `APP_DB_PASSWORD` estaba hardcodeada en `postgres/init/01-init.sql` como `changeme_app_strong_password`, lo que no coincidía con el valor en `.env`.

**Solución:**
- **`postgres/init/01-init.sql`**: Reescrito para usar variables de entorno del contenedor (`APP_DB_USER`, `APP_DB_PASSWORD`, `APP_DB_NAME`) mediante `\set` de psql
- **`docker-compose.yml`**: Agregadas las variables `APP_DB_USER`, `APP_DB_PASSWORD`, `APP_DB_NAME` al servicio `postgres`

### 3. Corrección de imagen de Evolution API

**Problema:** La imagen `atendai/evolution-api:v2.2.1` no existe en Docker Hub.

**Solución:** Corregido a `evoapicloud/evolution-api:v2.2.1` (posteriormente eliminado al migrar a Baileys).

### 4. Generación de claves seguras

- Generadas claves seguras para `EVOLUTION_API_KEY` y `FLASK_SECRET_KEY` usando Node.js `crypto.randomBytes`
- Ambas claves de 32 bytes en base64url
